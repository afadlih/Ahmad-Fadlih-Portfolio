# Content Provenance

This document explains where portfolio claims come from and how they should be reviewed.

## Uploaded CV

Used for the working baseline of:

- education;
- organization roles;
- Talk2Trainz role;
- Digital Marketing Professional credential;
- initial project descriptions;
- public contact links.

Records derived from the CV use:

```text
evidenceStatus: documented
```

They must not be described as verified until scans, links, photos, or owner-confirmed details are added.

## Connected GitHub repositories

Used to verify implementation paths for:

```text
InternLog AI
AquaSense
FormAI
```

Verification date stored in content:

```text
2026-07-27
```

Featured repositories are private. Public pages show file paths and implementation notes only. Direct blob links and commit SHAs are intentionally omitted.


## Public portrait

The portfolio currently uses an owner-approved professional portrait generated from the owner photo. The face is kept consistent with the supplied image, while clothing, background, and studio presentation are generated for portfolio use.

Stored status:

```text
photoStatus: owner-approved-generated-portrait
```

This portrait must not be described as an original studio photograph. It can be replaced later with an owner-supplied studio photo without changing the page layout.

## Owner knowledge

Required for:

- exact personal contribution;
- team division;
- sequence of failed attempts;
- measured impact;
- production usage;
- latest organization period;
- certificate date and number;
- LinkedIn alignment.

Until confirmed, project content keeps:

```text
contentReview: needs-owner-review
```

## Evidence status rules

### documented

Supported by CV or repository documentation, but final public evidence is incomplete.

### ready

A safe public artifact exists and has been reviewed for private data.

### verified

The artifact and its claim have been checked against a source that can be opened or independently confirmed.

## Placeholder rule

Placeholder screenshots and certificate frames are layout aids only. They are not evidence and cannot use `ready` or `verified` status.
